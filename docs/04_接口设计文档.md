## 1. 接口规范

### 1.1 通用约定
-   **协议**: HTTPS (TLS 1.3)
-   **数据格式**: JSON (UTF-8)
-   **认证**: Bearer Token (OAuth 2.0 Access Token)
-   **版本控制**: URL 路径版本 `/api/v1/...`
-   **时间格式**: ISO 8601 (`YYYY-MM-DDTHH:mm:ssZ`)

### 1.2 请求头规范
| Header | 必填 | 说明 |
|--------|------|------|
| Authorization | 是 | `Bearer <token>` |
| Content-Type | 是 | `application/json` |
| X-Request-ID | 否 | 请求追踪 ID，网关自动生成 |
| X-Idempotency-Key | 否 | 幂等键，写操作建议携带 |

### 1.3 响应格式
**成功响应**:
```json
{
  "code": 200,
  "message": "success",
  "data": { ... },
  "trace_id": "req_123456"
}
```
**错误响应**:
```json
{
  "code": 4001,
  "message": "Data format mismatch",
  "details": "Field 'email' is invalid",
  "trace_id": "req_123456"
}
```

## 2. 核心接口定义

### 2.1 系统管理接口

#### 2.1.1 注册系统
-   **URL**: `POST /api/v1/systems`
-   **描述**: 注册新的外部系统接入中枢。
-   **请求体**:
    ```json
    {
      "system_name": "SAP ERP",
      "system_type": "ERP",
      "protocol": "REST",
      "endpoint": "https://erp.example.com/api",
      "auth_config": { "type": "OAuth2", "client_id": "..." }
    }
    ```
-   **响应**: 返回 `system_id` 及 API 凭证。

#### 2.1.2 获取系统列表
-   **URL**: `GET /api/v1/systems?page=1&size=20`
-   **描述**: 分页查询已注册系统。
-   **响应**: 系统列表及分页信息。

### 2.2 数据映射接口

#### 2.2.1 创建映射规则
-   **URL**: `POST /api/v1/mappings`
-   **描述**: 定义源系统到目标系统的字段映射。
-   **请求体**:
    ```json
    {
      "mapping_name": "ERP_to_CRM_Customer",
      "source_system": "sys_erp",
      "target_system": "sys_crm",
      "field_mappings": [
        { "source": "$.cust_id", "target": "$.contact_id", "transform": "prefix('CRM_', $)" }
      ]
    }
    ```

### 2.3 流程编排接口

#### 2.3.1 部署流程定义
-   **URL**: `POST /api/v1/processes/deploy`
-   **描述**: 上传并部署 BPMN 2.0 流程文件。
-   **请求体**: `multipart/form-data`，包含 `bpmn_file`。
-   **响应**: 返回 `process_definition_id` 和版本号。

#### 2.3.2 启动流程实例
-   **URL**: `POST /api/v1/processes/{id}/instances`
-   **描述**: 根据流程定义启动新实例。
-   **请求体**: `{ "variables": { "order_id": "ORD-001" } }`

## 3. 错误码字典

| 错误码范围 | 类别 | 示例 | 处理建议 |
|------------|------|------|----------|
| 1000-1999 | 客户端错误 | 1001 参数校验失败 | 检查请求参数 |
| 2000-2999 | 认证授权 | 2001 Token 过期 | 刷新 Token |
| 3000-3999 | 业务逻辑 | 3001 系统未注册 | 先注册系统 |
| 4000-4999 | 数据集成 | 4001 格式不匹配 | 检查映射规则 |
| 5000-5999 | 流程编排 | 5001 流程未找到 | 检查流程 ID |
| 6000-6999 | 限流熔断 | 6001 频率超限 | 降低请求频率 |
| 9000-9999 | 系统内部 | 9001 服务不可用 | 联系运维 |

## 4. Webhook 与事件接口

### 4.1 事件订阅
-   **URL**: `POST /api/v1/subscriptions`
-   **描述**: 订阅特定事件，配置回调 URL。
-   **请求体**:
    ```json
    {
      "event_type": "system.status.changed",
      "callback_url": "https://my-app.com/webhook",
      "secret": "whsec_..." 
    }
    ```

### 4.2 事件推送格式
遵循 CloudEvents 1.0 标准:
```json
{
  "specversion": "1.0",
  "type": "system.status.changed",
  "source": "/integration-hub",
  "id": "evt_123",
  "time": "2026-04-10T10:00:00Z",
  "data": { "system_id": "sys_001", "status": "Active" }
}
```

## 5. 接口版本管理

-   **兼容性**: 向后兼容，破坏性变更必须升大版本 (v1 -> v2)。
-   **生命周期**: 旧版本保留 6 个月后下线。
-   **废弃通知**: 响应头 `Deprecation: true`, `Sunset: <date>`。
