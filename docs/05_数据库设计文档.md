## 1. 数据架构概述

### 1.1 存储引擎选型
| 数据类型 | 存储引擎 | 说明 |
|----------|----------|------|
| 结构化元数据 | PostgreSQL 16+ | 系统配置、API 定义、用户权限 |
| 缓存/会话 | Redis 7.2+ | 热点数据、Token、分布式锁 |
| 消息数据 | Kafka 3.6+ | 异步消息、事件流 |
| 审计/日志 | Elasticsearch 8.12+ | 操作日志、链路追踪、运行日志 |
| 流程实例 | Camunda ES | 流程执行历史、变量 |

### 1.2 数据生命周期
| 数据类别 | 热存储 | 温存储 | 冷存储 | 归档 |
|----------|--------|--------|--------|------|
| 业务元数据 | 永久 | - | - | 定期备份 |
| 运行时状态 | 30 天 | 90 天 | 1 年 | 删除 |
| 审计日志 | 30 天 | 180 天 | 3 年 | 合规归档 |
| 消息数据 | 7 天 | - | - | 消费即删 |

## 3. 核心表结构设计

### 3.1 系统注册表 (`t_system`)
| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| system_id | UUID | PK | 系统唯一标识 |
| system_name | VARCHAR(64) | Unique, Not Null | 系统名称 |
| system_type | VARCHAR(32) | Not Null | ERP/CRM/HRM 等 |
| protocol | VARCHAR(16) | Not Null | REST/gRPC/AMQP |
| endpoint | VARCHAR(255) | Not Null | 接入地址 |
| auth_config | JSONB | Not Null | 认证配置 (加密) |
| status | VARCHAR(16) | Not Null | Registered/Active/Inactive |
| created_at | TIMESTAMP | Default NOW() | 创建时间 |
| updated_at | TIMESTAMP | Default NOW() | 更新时间 |

**索引**:
-   `idx_system_name`: UNIQUE (`system_name`)
-   `idx_system_status`: (`status`)

### 3.2 API 定义表 (`t_api_definition`)
| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| api_id | UUID | PK | API 唯一标识 |
| system_id | UUID | FK, Not Null | 关联系统 |
| path | VARCHAR(255) | Not Null | API 路径 |
| method | VARCHAR(8) | Not Null | GET/POST/PUT/DELETE |
| version | VARCHAR(16) | Not Null | 语义化版本 |
| openapi_spec | JSONB | - | OpenAPI 片段 |
| mock_enabled | BOOLEAN | Default FALSE | 是否开启 Mock |

**索引**:
-   `idx_api_system_path`: (`system_id`, `path`, `method`)

### 3.3 路由规则表 (`t_route_rule`)
| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| rule_id | UUID | PK | 规则唯一标识 |
| api_version_id | UUID | FK, Not Null | 关联 API 版本 |
| priority | INT | Not Null | 优先级 (数值越大越高) |
| match_condition | JSONB | Not Null | 匹配条件 (Path/Header) |
| target_service | VARCHAR(128) | Not Null | 目标服务名 |
| config | JSONB | - | 路由配置 (权重/重写) |

### 3.4 字段映射表 (`t_field_mapping`)
| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| mapping_id | UUID | PK | 映射唯一标识 |
| mapping_name | VARCHAR(128) | Not Null | 映射规则名称 |
| source_system | UUID | FK, Not Null | 源系统 |
| target_system | UUID | FK, Not Null | 目标系统 |
| mappings | JSONB | Not Null | 字段映射数组 |
| validation_rules | JSONB | - | 校验规则 |

**Mappings JSON 示例**:
```json
[
  { "source": "$.id", "target": "$.user_id", "transform": "to_string($)" },
  { "source": "$.name", "target": "$.full_name" }
]
```

### 3.5 审计日志表 (`t_audit_log`)
*注: 实际存储于 Elasticsearch，此处定义逻辑结构*
| 字段 | 类型 | 说明 |
|------|------|------|
| log_id | UUID | 日志 ID |
| trace_id | VARCHAR(64) | 请求追踪 ID |
| user_id | UUID | 操作用户 |
| action | VARCHAR(64) | 操作类型 |
| resource | VARCHAR(255) | 操作资源 |
| ip_address | VARCHAR(45) | 客户端 IP |
| result | VARCHAR(16) | Success/Failure |
| details | JSONB | 详细信息 |
| created_at | TIMESTAMP | 操作时间 |
| hash_chain | VARCHAR(128) | 防篡改哈希链 |

## 4. 缓存设计 (Redis)

### 4.1 Key 命名规范
`{module}:{entity}:{id}`，例如 `sys:api:route:v1`。

### 4.2 核心缓存结构
| Key 模式 | 类型 | 说明 | TTL |
|----------|------|------|-----|
| `sys:config:{id}` | Hash | 系统配置 | 永久 |
| `sys:route:cache` | Hash | 路由规则缓存 | 5min |
| `auth:token:YOUR_SECRET}` | String | Access Token | 1h |
| `lock:resource:{id}` | String | 分布式锁 | 30s |
| `rate:limit:{key}` | Hash | 限流计数器 | 动态 |

## 5. 数据备份与恢复

### 5.1 备份策略
| 数据类型 | 备份方式 | 频率 | 保留周期 | 恢复目标 |
|----------|----------|------|----------|----------|
| PostgreSQL | pg_dump + WAL | 每日全量 + 实时 WAL | 30 天 | RPO ≤ 1min |
| Redis | RDB + AOF | 每小时 RDB + 每秒 AOF | 7 天 | RPO ≤ 5min |
| Elasticsearch | Snapshot | 每日快照 | 90 天 | RPO ≤ 1h |

### 5.2 恢复流程
1.  确认故障范围和数据损坏程度。
2.  从最近的有效备份点恢复数据。
3.  应用 WAL/增量日志至故障前时间点。
4.  校验数据一致性 (Count/Sum/Hash)。
5.  切换流量，观察系统状态。
