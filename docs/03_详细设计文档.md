## 2. M1 接入管理详细设计

### 2.1 系统注册流程
```mermaid
sequenceDiagram
    participant Admin
    participant Gateway
    participant M1 as 系统注册中心
    participant DB

    Admin->>Gateway: POST /systems
    Gateway->>M1: 转发请求
    M1->>DB: 检查名称唯一性
    alt 已存在
        M1-->>Admin: 409 Conflict
    else 不存在
        M1->>M1: 生成 SystemID & API Key
        M1->>DB: 插入记录
        M1-->>Admin: 200 OK + 凭证
    end
```

### 2.2 核心数据结构
**SystemEntity**:
| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| system_id | UUID | PK | 全局唯一标识 |
| system_name | String(64) | Unique, Not Null | 系统名称 |
| protocol | Enum | Not Null | REST/gRPC/AMQP |
| auth_config | JSON | Not Null | 加密存储认证信息 |
| status | Enum | Not Null | Registered/Active/Inactive |

## 3. M2 路由与流量控制详细设计

### 3.1 动态路由匹配算法
采用**规则树 (Rule Tree)** 匹配，优先级:
1.  精确匹配 (Path)
2.  前缀匹配 (Path Prefix)
3.  Header 匹配 (灰度/多租户)
4.  权重路由 (Canary)

### 3.2 限流算法实现
-   **令牌桶**: 适用于允许突发流量的场景。
    ```java
    class TokenBucket {
        long capacity;
        long tokens;
        long refillRate;
        long lastRefillTime;
        
        boolean tryConsume() {
            refill();
            if (tokens > 0) {
                tokens--;
                return true;
            }
            return false;
        }
    }
    ```
-   **熔断器状态机**: Closed -> Open (失败率>50%) -> HalfOpen (60s 后) -> Closed/Open。

## 4. M3 数据集成详细设计

### 4.1 转换引擎架构
```mermaid
flowchart LR
    Input --> Parser[解析器]
    Parser --> IM[中间模型 JSON]
    IM --> Transformer[转换执行器]
    Transformer --> Serializer[序列化器]
    Serializer --> Output
```

### 4.2 字段映射执行
1.  加载映射规则 (JSONPath + 表达式)。
2.  构建映射 DAG (有向无环图)。
3.  按拓扑排序顺序执行转换函数。
4.  组装目标对象。

### 4.3 校验失败策略
-   **Reject**: 进入死信队列 (DLQ)。
-   **Default**: 使用默认值。
-   **Alert**: 记录告警并继续。

## 5. M4 流程编排与 Saga 详细设计

### 5.1 Saga 事务协调
```mermaid
sequenceDiagram
    participant Client
    participant Orchestrator
    participant SvcA
    participant SvcB

    Client->>Orchestrator: Start Saga
    Orchestrator->>SvcA: Action A
    SvcA-->>Orchestrator: Success
    Orchestrator->>SvcB: Action B
    SvcB-->>Orchestrator: Fail
    Orchestrator->>SvcA: Compensate A
    SvcA-->>Orchestrator: Success
    Orchestrator-->>Client: Saga Failed
```

### 5.2 补偿机制
-   每个 Action 必须定义 `CompensationAction`。
-   补偿失败重试 3 次，仍失败则转入人工处理队列。

## 6. M5 安全管控详细设计

### 6.1 鉴权流程
```mermaid
flowchart TD
    Req --> AuthN{已认证?}
    AuthN -- 否 --> 401
    AuthN -- 是 --> RBAC{角色权限}
    RBAC -- 拒绝 --> 403
    RBAC -- 通过 --> ABAC{属性策略}
    ABAC -- 拒绝 --> 403
    ABAC -- 通过 --> Forward[转发请求]
```

### 6.2 审计日志防篡改
-   日志写入后计算 `Hash(Current) = SHA256(Content + Hash(Previous))`。
-   形成哈希链，任何修改都会导致后续哈希不匹配。

## 7. 异常处理与重试

### 7.1 全局异常拦截
统一捕获异常，返回标准错误格式:
```json
{
  "error": { "code": "4001", "message": "...", "trace_id": "..." }
}
```

### 7.2 重试策略
-   **指数退避**: `delay = base_delay * 2^attempt`。
-   **最大重试**: 3 次。
-   **幂等性**: 通过 `Idempotency-Key` Header 保证。
